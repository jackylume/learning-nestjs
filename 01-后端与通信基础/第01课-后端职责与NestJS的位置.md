# 第 01 课：后端职责与 NestJS 的位置

## 学习目标

学完本课，你应能：

1. 说清楚「后端」在一个完整应用中负责什么、不负责什么；
2. 理解前端、后端、数据库三者的分工与协作方式；
3. 解释为什么不能只用前端、为什么后端代码不能写在浏览器里；
4. 说出 NestJS 是什么、处于什么位置，以及为什么要用框架而不是裸写 Node.js。

## 场景与原理

### 1. 一个请求背后的分工

想象你在外卖 App 上点了一份餐。你看到的页面、按钮、图片——这些是**前端**（浏览器/App 里运行的代码）。但前端自己并没有菜单数据、不知道你的账号余额、也不能真的通知餐厅，它必须向一台远程的**服务器**要数据、下指令。

服务器上运行的程序就是**后端**。它做的事情可以归纳为五类：

| 职责 | 说明 | 例子 |
|---|---|---|
| 接收与响应请求 | 监听网络，按约定格式接收请求、返回结果 | 收到「查询菜单」请求，返回 JSON 数据 |
| 业务逻辑 | 实现这个产品的核心规则 | 满减计算、库存扣减、订单状态流转 |
| 数据存取 | 把数据安全地读写进数据库 | 保存订单、查询历史订单 |
| 安全与权限 | 验证身份、控制谁能干什么 | 未登录不能下单；商家不能改别人的店 |
| 与其他系统协作 | 调用支付、短信、第三方接口 | 发起微信支付、发短信通知 |

**数据库**则是后端旁边的「仓库」：数据真正持久化存放的地方。后端是唯一被允许直接操作数据库的角色——前端绝不能直连数据库。

整体协作关系：

```
浏览器/App（前端）  ──HTTP请求──▶  服务器（后端/NestJS）  ──SQL──▶  数据库
        ◀──JSON响应──              ◀──查询结果──
```

### 2. 为什么业务逻辑必须放在后端

一个常见的初学者疑问：「校验、计算这些逻辑，JavaScript 在前端也能写，为什么还要后端？」

核心原因：**前端代码运行在用户的设备上，你完全无法控制它。**

- 用户可以用浏览器开发者工具随意修改前端代码、跳过校验；
- 用户可以绕过你的页面，直接用工具（如 curl）伪造请求发给你的服务器；
- 前端里的任何「秘密」（密钥、内部逻辑）对用户都是可见的。

所以铁律是：**前端做体验，后端做把关。** 前端校验是为了给用户即时反馈（体验好），后端必须重新校验一切（安全性），永远不要信任客户端传来的任何数据。

### 3. NestJS 的位置

后端可以用很多语言写（Java、Go、Python、Node.js…）。**Node.js** 让 JavaScript 可以运行在服务器上。但裸 Node.js 只提供了很底层的能力（监听端口、读写流），写一个真实项目时你会反复手写：路由分发、参数解析、错误处理、模块组织……

**框架**就是把这些通用问题解决好，并给你一套组织代码的规范。NestJS 的定位：

- 基于 Node.js 的服务端框架（底层默认用 Express，也可切换 Fastify）；
- 用 TypeScript 和面向对象/装饰器的方式组织代码，自带「依赖注入」等工程化能力；
- 约定了一套清晰的结构（Controller 管请求、Service 管逻辑、Module 管组织——这正是第三阶段要学的）。

类比：Node.js 是发动机，NestJS 是造好的整车。你直接开车（写业务），而不用先造轮子。

## 示例

一个最简的 NestJS 接口长这样（现在只需要「看懂意图」，不要求会写）：

```ts
// menu.controller.ts
@Controller('menu')          // 这个类负责处理 /menu 开头的请求
export class MenuController {
  @Get()                     // 处理 GET /menu
  findAll() {
    return [{ id: 1, name: '红烧肉', price: 28 }];
  }
}
```

启动后，浏览器访问 `http://localhost:3000/menu`，就会收到这段 JSON。框架帮你完成了：监听端口、解析请求、匹配路由、把返回值序列化成 JSON 并回发——你写的只是「业务上该返回什么」。

## 常见误区

1. **「前端校验过了，后端可以信任数据」** —— 错误。客户端的一切输入都必须视为不可信，后端必须重新校验。
2. **「后端就是数据库的搬运工」** —— 错误。CRUD 只是基础，后端的核心价值是业务规则、权限、一致性、性能。
3. **「把密码、密钥写在前端代码里也没关系」** —— 错误。前端的一切对用户可见，秘密只能存在后端。
4. **「学了框架就不用懂 HTTP 了」** —— 错误。框架封装的是 HTTP，不理解它，遇到问题（跨域、状态码、缓存）会无从下手。这正是第 02～06 课的内容。
5. **「数据库可以直接暴露给前端访问」** —— 极其危险。数据库只接受来自后端的连接。
